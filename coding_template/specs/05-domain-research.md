## 研究目录分类

目标项目中研究产物默认按以下目录分类：

```text
docs/research/
├── 05-domain-research.md
├── competitors/
├── data-sources/
├── data-lineage/
├── user-flows/
├── evidence/
└── assumptions.md
```

分类说明：

- `competitors/`：同类产品、竞品、标杆产品分析。
- `data-sources/`：数据来源、授权方式、可信度、更新频率、失败模式。
- `data-lineage/`：数据从来源到存储、API、页面、回写和审计的链路。
- `user-flows/`：用户从进入产品到完成核心目标的闭环。
- `evidence/`：外部链接、截图、API 文档摘要、访谈纪要或其他证据。
- `assumptions.md`：待确认假设、阻塞问题和确认责任人。

## 验证要求

进入 Architecture / System Design 前必须满足：

- 至少分析 3-5 个同类或竞品产品；不适用时必须说明原因。
- 每个核心页面字段能追溯到 `SRC` / `MAP`，或明确标记为待确认假设。
- 每类核心数据说明来源、可信度、更新频率、失败模式和授权方式。
- 至少有一个用户使用闭环 `LOOP` 和一个数据流闭环 `FLOW`。
- P0 数据风险、数据模型映射或用户闭环不清楚时，不进入 Architecture / System Design。
